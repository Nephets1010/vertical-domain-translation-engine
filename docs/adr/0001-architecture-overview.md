# ADR-0001 总体架构与分层

- 状态：已采纳（2026-11-08）
- 决策人：交付总监 Qi（主理人）

## 背景

基于用户提供的《十大AI项目设计文档汇编》中「项目三 垂直领域专业术语机器翻译引擎」
构建企业级生产系统。用户原始详细需求（知识图谱 / 风险预警 / 智能投研）对应文档中的
「项目五」，存在标题与需求的矛盾。用户已确认：**按标题做项目三（翻译引擎）**，
并将"图谱/风险/投研"需求重新对齐到翻译引擎语境。

## 决策

采用「数据驱动 + 模型服务」双环架构（源自文档项目三设计），并补齐企业级横切能力：

```
            ┌──────────── 数据接入与清洗 (M1) ────────────┐
            │  采集 → 去噪对齐 → 质量评分                  │
            └──────────────────────┬──────────────────────┘
                                   ▼
            ┌──────────── 术语抽取与术语库/网络 (M2) ──────┐
            │  对齐词抽取 → 置信度排序 → 术语库 → 术语网络  │
            └──────────────────────┬──────────────────────┘
                                   ▼
            ┌──────────── 领域微调 (M3) ──────────────────┐
            │  LoRA 数据格式化 → 训练 → 模型版本登记        │
            └──────────────────────┬──────────────────────┘
                                   ▼
  术语库 ──▶ 术语约束注入 ──▶ 翻译服务 (M4) ──▶ 批量文档翻译 (M6)
                                   │
                                   ▼
            ┌──────────── 质量风险规则引擎与评分 (M5) ─────┐
            │  COMET/词法打分 + 术语命中率 → 风险规则 → 告警 │
            │  → 错误回流（术语库热更新）                    │
            └───────────────────────────────────────────────┘
                                   ▲
            ┌──────────── 翻译智能分析 (重映射) ───────────┐
            │  关联挖掘 / 相似错误案例 / 质量报告摘要        │
            └───────────────────────────────────────────────┘

  横切：配置管理 / 结构化日志 / 统一异常 / 服务接口层(API) /
        任务调度(APScheduler) / 监控告警(Prometheus+AlertManager)
```

分层（代码）：`config` → `db/models` → 领域模块(`corpus`,`terminology`,`training`,
`translation`,`quality`,`analytics`) → `api`(接口层) → `scheduler`/`monitoring`(横切)。

## 后果

- 模块边界清晰、可独立测试与替换（翻译器/评估器均以适配器接口隔离）。
- 离线可运行：默认 `mock` 翻译器 + SQLite，无需 GPU/Postgres 即可跑通全流程与测试。
- 生产可通过环境变量切换到 vLLM / API 翻译器、PostgreSQL、Elasticsearch、Redis。

## 备选

- 微服务拆分：过早拆分增加运维成本，中小规模（<100万）不必要。否决。
- 纯脚本流水线：缺乏服务化与监控，不符企业级要求。否决。
