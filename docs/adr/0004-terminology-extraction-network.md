# ADR-0004 术语抽取与术语网络（模块 M2）

- 状态：已采纳（Phase 2）
- 日期：2026-11-08

## 背景
需要从平行语料中低成本地发现候选术语，并构建"术语网络"（同义/共现等关系）以支撑
翻译术语约束与后续智能分析（关联挖掘）。

## 决策
1. **抽取方法**：源端英文按词取 1~3 元词组（过滤停用词及首尾停用词），目标端中文按字取
   2~4 元字串；以"源词组—目标字串共现一致性"为信号，置信度 = 最常共现目标占比。
   确定性、可复现、可回归。
2. **精炼规则**：单 token 映射至多字目标（>2 字）视为片段丢弃；短语互为子串且同目标时
   仅保留更凝练者。避免"merger"与"merger agreement"并存噪声。
3. **权威词典优先**：随项目提供的 `terms.csv` 为权威术语源；抽取结果 `source=extracted`，
   仅在 literal+domain 不存在时入库，绝不覆盖人工术语。
4. **术语网络**：`TermRelation`（源/目标 term_id + relation_type + weight + 证据）。
   `suggest_network` 由"同译文=同义""同句共现=cooccurrence"自动建边，降低人工成本。
5. **检索**：默认 DB `LIKE` 子串（PG/SQLite 通用）；可选 Elasticsearch 适配层已留接口。

## 影响
- 术语约束翻译（Phase 4）直接消费 `term` 表。
- 关联挖掘（Phase 6）消费 `term_relation` 表。

## 局限与替代方案
- 纯共现法对低频/长术语召回有限，且无真正词对齐。生产应叠加对齐模型（如 fast_align）或
  向量检索；本决策以词典为权威、抽取为补充，符合"离线可跑、可审计"的工程约束。
- 曾考虑用 LLM 抽取：成本与不确定性高，否决。
