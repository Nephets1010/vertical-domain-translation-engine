# ADR-0002 存储选型

- 状态：已采纳（2026-11-08）
- 决策人：架构师 Gao

## 背景

需求规模：中小规模（<100 万实体/句对），单机 Docker Compose 部署。需支持语料、
术语库、术语网络（图谱）、任务、评估、风险告警等结构化数据，并支持术语检索与溯源。

## 决策

| 数据 | 存储 | 理由 |
|------|------|------|
| 语料 / 术语 / 任务 / 评估 / 风险 / 溯源 | PostgreSQL（主库） | ACID、关系清晰、迁移用 Alembic、Docker 就绪 |
| 术语检索（可选） | Elasticsearch | 大规模全文/模糊检索；小规模可由 PG trigram 替代，默认关闭 |
| 缓存 / 任务信号 | Redis（可选） | 高速缓存术语、限流；本地无 Redis 时降级为内存，默认关闭 |
| 模型权重 / 适配器 | 本地文件系统（HF_CACHE_DIR） | 不入库，路径登记到 model_version 表 |

开发/测试默认 SQLite（零依赖、可离线跑），生产用 PostgreSQL——**同一套 SQLAlchemy
模型与迁移**，通过 `DATABASE_URL` 切换。

## 后果

- 单一事实源在关系库，图谱（术语网络）以 `term_relation` 表表达，规模可控时无需专用图库。
- ES 作为可选增强层，接口化隔离（`terminology.store` 提供 PG/ES 双实现），避免耦合。

## 备选

- Neo4j 图数据库：术语网络规模小（<百万），引入图库运维过重。否决（预留扩展点）。
- 纯向量库（如 Milvus）：术语检索以精确/trigram 为主，向量仅用于消歧近似，非必需。否决。
